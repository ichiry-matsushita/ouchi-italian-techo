# 原稿 → 記事 変換ルール

メモ書きの原稿（`drafts/<フォルダ>/draft.txt`）と写真を、このサイトの記事テンプレートに沿った記事ファイル（`src/articles/<スラッグ>/index.md`）に変換するためのルールです。
`/new-article` コマンドが、このファイルを読んでから変換します。

見本として、手で書いた記事 `src/articles/cacio-e-pepe/index.md` を必ず先に読み、書き方と文の長さをそろえてください。

---

## 0. いちばん大事なこと

- **原稿に書かれていないことは作らない。**
  分量・時間・人数・温度・回数・地名・由来・食材など、事実にあたることを推測で埋めてはいけません。
  わからないところは `TODO:` で始まる短いメモを入れて残します（書き方は「6. TODO の書き方」）。
- 料理の一般的な知識で「たぶんこうだろう」と補うのも禁止です。人が後で確認して直します。
- 原稿の内容を削りすぎないこと。原稿にあるコツ・注意・きっかけは、どこかの部品に必ず入れます。

---

## 1. フロントマター

```yaml
---
title: "記事タイトル"
description: "一覧やSNSで表示する説明"
date: 2026-11-20
category: "パスタ"
tags: ["トマト", "ローマ料理"]
cookingTime: 40
servings: 2
region: "ラツィオ州"
eyecatch: "./images/01.jpg"
eyecatchAlt: "写真の説明"
---
```

| 項目 | ルール |
|---|---|
| `title` | 原稿の料理名をもとに、何の料理か・どんな特徴かがわかる 20〜35 文字。料理名は必ず入れる。例：「チーズと黒こしょうだけで作る、カチョ・エ・ペペ」 |
| `description` | 90〜110 文字。どんな料理か＋この記事でわかること（コツなど）。原稿にある内容だけで書く |
| `date` | 原稿に日付があればそれ。なければコマンドを実行した日（YYYY-MM-DD） |
| `category` | `前菜` / `パスタ` / `メイン` / `ドルチェ` のどれか1つ（下の表で判断） |
| `tags` | 2〜4 個。主な食材や料理の種類を、原稿に出てくる言葉から選ぶ |
| `cookingTime` | 調理時間（分）の**数字だけ**。原稿に合計時間があればそれ。手順ごとの時間しかなければ足し算してよい（ただし「ひと晩」「寝かせる」など不明な時間を含むなら TODO） |
| `servings` | 何人分かの**数字だけ**。原稿が「4個分」「4枚分」のように個数で書かれていて、1人1個と読めるときはその数字にし、最後の報告で「4個分を4人分としました」と伝える |
| `region` | 原稿に発祥の地域（州）が書いてあるときだけ書く。**書いていなければ項目ごと消す**（TODO にはしない） |
| `eyecatch` | 1枚目の写真 `./images/01.jpg` |
| `eyecatchAlt` | 1枚目の写真の説明（「5. 写真」） |

### カテゴリの判断

| カテゴリ | 当てはまるもの |
|---|---|
| 前菜 | 食事の最初に出す軽い料理。サラダ、ブルスケッタ、マリネ、スープなど |
| パスタ | パスタ・ニョッキ・リゾットなど、主食になる料理 |
| メイン | 肉や魚が主役の一皿 |
| ドルチェ | デザート、お菓子 |

原稿にカテゴリが書いてあればそれに従います。判断に迷うときは近いほうを選び、コマンドの最後の報告で「カテゴリは○○にしました（理由）」と伝えます。

## 2. 本文の組み立て

本文は、次の5つの部品を**この順番で、1回ずつ**使って書きます。見出し（`##`）は部品が自動で出すので、記事ファイルには書きません。

```
{% lead %} … {% endlead %}
{% ingredients %} … {% endingredients %}
{% steps %} … {% endsteps %}
{% point %} … {% endpoint %}
{% summary %} … {% endsummary %}
```

`{% figure %}`（写真＋キャプション）だけは、必要なときに `steps` と `point` の間などに入れてかまいません。

### リード `{% lead %}`
- 2〜3 文。「どんな料理か」と「作ってみたきっかけ」。
- きっかけが原稿になければ、どんな料理かだけでよい（作らない）。

### 材料 `{% ingredients %}`
- 1行に1つ、`材料名 | 分量 | 代わりの食材` の形。代わりがなければ3つ目は省略。
  ```
  スパゲッティ | 160g
  ペコリーノ・ロマーノ | 60g | パルミジャーノ・レッジャーノ
  ```
- 材料をグループに分けたいときは、`[ソース]` のように角かっこだけの行を入れる。
- 分量の書き方をそろえる：`g` `ml` `大さじ1` `小さじ1/2` `1個` `少々` `適量`。全角数字は半角にする。
- **代わりの食材は、原稿に書いてあるときだけ**入れる。
- 原稿に分量がない材料は、分量の欄を `TODO: 分量` にする。

### 手順 `{% steps %}`
- 空行で区切った1かたまりが1手順。番号は自動で付くので書かない。
- 1手順は 1〜3 文。長い手順は分ける。1つの手順に作業を詰め込みすぎない。
- 写真は、その手順の中に `![写真の説明](./images/02.jpg)` の行を1つ入れる（「5. 写真」）。
- 原稿にある火加減・時間・目安（「色づくまで」など）は省かずに残す。

### ポイント `{% point %}`
- 原稿のコツ・注意・失敗談を、コツごとに `### 見出し` で区切る。見出しは 20 文字以内で、何をすればいいかがわかる言い方にする（例：「チーズは必ず火を止めてから」）。
- 各コツの本文は 1〜3 文。
- 原稿にコツが1つもなければ、`TODO: 原稿にコツの記載がありません` だけを書く。

### まとめ `{% summary %}`
- 1〜2 文。記事全体をふり返る一言。原稿にある内容から書き、新しい情報は足さない。
- まとめは文を考えて書く部品なので、事実を足しやすい。「作り置きできる」「日持ちする」「子どもにも人気」など、原稿にない性質を書いていないか、書き終えたら原稿と見比べる。

## 3. 文体

- **です・ます調**にそろえる。原稿が話し言葉・箇条書きでも、文章に直す。
- 1文は短く。目安は 40 文字前後、長くても 60 文字まで。
- 1文1行で書く（表示のときは自動でつながる）。
- やさしい言葉を使う。専門用語は、原稿で使われているものだけ使う。
- 「〜しましょう」「〜してください」の呼びかけは、ポイントとまとめで少しだけ使う。
- 「！」や絵文字、「♪」は使わない。
- 一人称は使いすぎない（「私は」を毎文入れない）。

---

## 4. スラッグ（記事のURL）

- 原稿フォルダ名の先頭の日付（`2026-11-` など）を取ったものを使う。
  例：`drafts/2026-11-amatriciana` → `amatriciana`
- 半角英小文字・数字・ハイフンだけ。日本語やアンダースコアは使わない。
- 次の名前はカテゴリのURLとぶつかるので使えない：`antipasto` `pasta` `secondo` `dolce` `page`
- 同じ名前の記事フォルダがすでにある場合は、上書きせずに止めて確認する。

---

## 5. 写真

- 写真は `scripts/import-photos.js` で記事フォルダにコピーする。位置情報などのメタデータを消して、`01.jpg` `02.jpg` … の名前にそろえる。原稿フォルダの写真を直接コピーしない。
- **ファイル名の番号順に**割り当てる。
  - 1枚目（`01.jpg`）→ 完成写真（アイキャッチ）
  - 2枚目以降 → 手順の写真。手順の順番どおりに、1手順に1枚まで。
- 各写真を実際に見て、どの手順の写真かを判断する。番号の順番は崩さない（3枚目を2枚目より前の手順に入れない）。
- 当てはまる手順がない写真や、手順より写真が多いときは、`{% figure %}` で `steps` の後ろに入れる。
- **代替テキスト（alt）は必ず書く。** 写真を見て、写っているものを 20〜50 文字で具体的に説明する。
  - よい例：「フライパンで粗びきの黒こしょうを乾煎りしているところ」
  - 悪い例：「写真」「手順2」「おいしそうなパスタ」
  - 写真から読み取れないこと（味、量など）は書かない。

---

## 6. TODO の書き方

原稿にない情報は、`TODO:` を付けて残します。チェックスクリプト（`npm run check:articles`）が見つけて一覧にするので、人が埋めてから公開します。

| 場所 | 書き方 |
|---|---|
| フロントマターの数字 | `cookingTime: "TODO: 調理時間が原稿にありません"` |
| フロントマターの文字 | `title: "TODO: 料理名が原稿にありません"` |
| 材料の分量 | `ペコリーノ・ロマーノ | TODO: 分量` |
| 手順の中 | `パスタをゆでます（TODO: ゆで時間）。` |
| 部品まるごと | `TODO: 原稿にコツの記載がありません` |

TODO は「何が足りないか」がわかる短い言葉にします。

---

## 7. 変換が終わったら

最後に、次を短く報告します。

1. 作った記事ファイルのパスと、スラッグ
2. フロントマターで判断したこと（カテゴリ、調理時間を足し算したか、など）
3. 写真の割り当て（どの写真をどこに使ったか）と、位置情報を消した写真の枚数
4. 残した `TODO:` の一覧
5. チェックスクリプトの結果
